# MUSKY DOSE — UNIVERSAL PLATFORM GOVERNANCE (V1.0)
**Production Platform:** [https://muskydose.in](https://muskydose.in)
**Repository:** `muskydose/musky`
**Authority:** Centralized Architecture Directive

---

## 1. Core Principle
> **“Nothing enters, changes, publishes, ranks, sells, tracks, automates, or leaves the Musky Dose platform without passing through the appropriate layer of the central governance system.”**

No domain, feature, API route, or background automation may create an independent competing rule framework. Data input is a suggestion; Centralized Governance is the authority.

---

## 2. Rule Hierarchy (Levels 0 to 6)

Every read, write, query, and presentation on the platform resolves through 7 distinct invariant layers:

```
Level 0: INFRASTRUCTURE & ENVIRONMENT INVARIANTS
         (Supabase connection, Edge config, Storage buckets)
         ▼
Level 1: FAIL-CLOSED INTEGRITY & CIRCUIT BREAKING
         (Never resurrect stale mock/seed data; empty DB = empty/404)
         ▼
Level 2: UNIVERSAL GOVERNANCE CORE (lib/governance)
         (Entity registry, authority precedence, invariant rules)
         ▼
Level 3: DATABASE SOURCE OF TRUTH
         (Supabase PostgreSQL rows & validated settings)
         ▼
Level 4: CASCADE REFERENCE INTEGRITY & PRUNING
         (Purge deleted entity references from menus, layouts, and relations)
         ▼
Level 5: SURFACE COMPOSERS & ADMINISTRATIVE GATES
         (requireAdminAuthAndCsrf, SEO Composer, Merchant Feeds)
         ▼
Level 6: EDGE CACHE & CLIENT CONSUMPTION
         (Next.js ISR, SWR, Browser LocalStorage)
```

---

## 3. Source of Truth & Precedence
The platform enforces strict authority precedence:

$$\text{EXPLICIT ADMIN MUTATION} > \text{DATABASE ROW} > \text{GOVERNANCE AUTO POLICY} > \text{AI SUGGESTION} > \text{DERIVED CACHE} > \text{SEED FIXTURE}$$

- **The Fail-Closed Mandate:** If a query to Supabase returns 0 rows or fails, the service MUST return `[]` or HTTP 404. It must NEVER resurrect static seed arrays (`INITIAL_*` in `lib/data-store.ts`).
- `lib/data-store.ts` is strictly a **Seed / Migration Fixture Asset**. Operational readers in `lib/db/*` must never import `INITIAL_*` as an operational fallback.

## 5. Lifecycle & 9-State Governance Model
Every governed entity moves through a defined state machine:

1. **`AUTO`**: Deterministically generated by platform governance (e.g. standard category auto-guides).
2. **`MANUAL`**: Explicitly set by an authenticated administrator.
3. **`LOCKED`**: Hard-locked by an admin; AI and automations cannot modify without explicit unlock.
4. **`NEEDS_REVIEW`**: Assigned to AI drafts, imports, or public submissions pending admin verification.
5. **`PUBLISHED`**: Publicly visible on storefront, searchable, and indexable in sitemaps.
6. **`UNPUBLISHED`**: Stored in DB but suppressed from public storefront and sitemaps.
7. **`ARCHIVED`**: Historical record preserved for auditing, accounting, and order history.
8. **`DELETED`**: Terminal state; triggers cascade reference pruning.
9. **`REJECTED`**: AI suggestion or invalid submission explicitly rejected.

**Precedence Invariant:** Lower-priority policies can never overwrite `LOCKED` or `MANUAL` records.

---

## 6. Validation & Invariants
Before an entity is persisted to the database:
- It must pass `UniversalGovernanceCore.validateEntity(entityType, payload)`.
- Product prices must be non-negative; compare price must exceed selling price or remain `null`.
- Variant pricing must be monotonic: larger pack weights cost more in total, but less per unit.
- Category names and page titles must be non-empty and generate sanitized URL-safe slugs.

---

## 7. Permissions & Admin Mutation Gate
- **Rule:** Every administrative mutation (`POST`, `PUT`, `PATCH`, `DELETE`) must pass through `requireAdminAuthAndCsrf(req)` from `lib/admin-middleware.ts`.
- Validates the HMAC-SHA256 signed admin session cookie and verifies trusted `Origin` / `Referer` headers.
- Public customer mutation paths are strictly isolated to `/api/orders` (rate-limited) and `/api/wholesale` (rate-limited).

---

## 8. AI & Automation Rules
Governed by `lib/governance/ai-governance.ts`:
- **AI Suggests. Governance Decides. Admin Confirms.**
- AI-generated outputs (Auto-Fill, SEO drafts, Keyword universes) carry:
  - `source: 'AI_AUTOFILL'`
  - `confidenceScore: number` (0.0 to 1.0)
  - `status: 'NEEDS_REVIEW'`
- AI outputs are NEVER directly written to authoritative storage without an explicit admin click and review.
- Attributes claimed by AI must match verified botanical entities; unverified claims are suppressed.

---

## 9. Delete & Cascade Reference Pruning Rules
Governed by `lib/governance/reference-integrity.ts`:
When any governed entity is deleted or unpublished:
- All references are pruned from `site_settings.layoutControls` (featured carousels, slides, trust strips).
- All navigation links (header, footer) pointing to the entity's slug or ID are removed.
- Cross-references (e.g., related products in guides, parent categories in products) are cleaned.
- Deleted entities NEVER resurrect.

---

## 10. SEO, Content & Zero-Fabrication Rules
- Canonical metadata is deterministically resolved by `lib/growth/intelligence-seo-composer.ts`.
- Canonical base is locked to `https://muskydose.in/<canonical-path>`.
- Zero unsupported botanical claims, zero fake reviews, zero fabricated metrics.
- Unindexed (`robotsIndex: false`) or unpublished entities are automatically excluded from `app/sitemap.ts`.

---

## 11. Commerce & Pricing Invariants
Governed by `lib/governance/commerce-governance.ts`:
- **Order Total Verification:** `total === (subtotal - discount + shipping)`. Orders are rejected with HTTP 400 if client-calculated totals do not match server arithmetic.
- **Variant Monotonicity:** Larger pack sizes must have higher total price and non-increasing unit price.
- **Wholesale MOQ:** Bulk wholesale requests require meeting minimum order volume thresholds.
- **Durable Idempotency:** Order submissions are guarded against serverless replay via durable keys.

---

## 12. Media & Storage Governance
- Direct Base64 string payloads in catalog database rows are strictly prohibited (rejected with HTTP 400).
- All image assets must be uploaded via `app/api/admin/media` to the Supabase `product-media` bucket.
- SVGs are sanitized to strip embedded `<script>` tags and malicious attributes.

---

## 13. Settings Governance & Domain Partitioning
- `site_settings` updates must validate allowed domain properties.
- Updating one section (e.g., WhatsApp ordering settings) must never clobber sibling sections (e.g., layout controls).
- Empty arrays (such as zero custom pages or zero certificates) must persist cleanly as `[]` rather than falling back to default fixtures.

---

## 14. Guardian Observability & Circuit Breaking
- Website Guardian (`lib/guardian/guardian-core.ts`) monitors synthetic health across L0 to L4.
- **Safety Boundary:** Guardian is an observability engine, NOT an uncontrolled business data mutator.
- Guardian auto-recovery is restricted to bounded actions (cache tag clearing, heartbeat resets) and never modifies product catalogs or commercial orders.

---

## 15. Performance, Caching & Revalidation
- Governed by `lib/revalidation.ts` (`revalidateEntitySurfaces`).
- Every mutation automatically purges relevant Next.js cache tags (`products`, `categories`, `guides`, `pages`, `site_settings`) and revalidates affected paths.

---

## 16. How Future Developers Add a New Feature
1. Open `lib/governance/types.ts` and add the new type to `UniversalEntityType`.
2. Open `lib/governance/entity-registry.ts` and call `registerGovernedEntity({ ... })`:
   - Declare the authoritative database table.
   - Declare whether admin auth & CSRF are required.
   - Implement the entity `validate` function.
   - Define revalidation paths and tags.
   - Define `onDeleted` cascade cleanup logic.
3. Use `UniversalGovernanceCore.validateEntity()` in your API routes.
4. Use `requireAdminAuthAndCsrf(req)` on administrative mutation endpoints.

---

## 17. Forbidden Bypass Patterns
1. **NO** `import { INITIAL_* } from '@/lib/data-store'` inside runtime database modules (`lib/db/*`).
2. **NO** silent fallback to seed data when a database table is empty.
3. **NO** direct Base64 images stored in database columns.
4. **NO** unauthenticated admin mutation routes.
5. **NO** AI-generated values auto-committed without human administrative review.
6. **NO** deletions that leave dangling IDs in layout controls or navigation menus.
